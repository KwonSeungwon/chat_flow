# ChatFlow 경량화(검색·AI 요약·ES·Kafka 제거) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 채팅 기능은 그대로 두고 search-service, ai-summary-service, Elasticsearch, Kafka, outbox 발행, 관련 프론트 UI를 제거해 운영 노드를 chat·gateway·frontend + Postgres·Valkey로 줄인다.

**Architecture:** 메시지는 이미 `ChatPersistenceService`에서 동기 저장되고 outbox는 Kafka 발행 전용이므로, outbox 쓰기와 Kafka 계층만 걷어낸다. 입장/퇴장 브로드캐스트는 outbox 메서드에 묶여 있어 `publishEvent` 직접 호출로 바꾼다. 모듈·차트·CI·인프라 정의를 지우고, 프론트에서 검색/AI 진입점을 지운다.

**Tech Stack:** Spring Boot 3.2 (Java 17, Gradle), Flutter 3.41 / Riverpod 2, Helm, K3s.

**Spec:** `docs/superpowers/specs/2026-10-16-wiki-dungeon-design.md` (section ①)

**Removal map (상세 줄 번호):** `.superpowers/notes/slim-removal-map.md` — 각 태스크 구현자는 이 파일의 해당 절을 먼저 읽는다.

## Global Constraints

- 메시지 송신 → DB 저장 → STOMP 브로드캐스트 → 히스토리 조회 → 편집·삭제, 그리고 입장/퇴장(JOIN/LEAVE) 브로드캐스트가 그대로 동작해야 한다. 최우선 회귀 기준.
- `outbox_events` 테이블과 기존 Flyway 마이그레이션(V1~V18)은 지우거나 고치지 않는다. 새 마이그레이션도 만들지 않는다.
- 유지: 채팅, 방 관리, 초대, 멘션(멘션 화면의 scrollToMessageId 하이라이트 포함), 예약 메시지, 파일, FCM, 읽음 상태, gateway `/api/users/search`(사용자 검색).
- DB 컬럼과 와이어 필드 `isAiGenerated`, enum 값 `AI_SUMMARY`는 옛 행 호환을 위해 백엔드에 남긴다.
- 시크릿 값을 파일에 쓰지 않는다. 플레이스홀더만.
- 검증: `./gradlew build` EXIT 0, `cd frontend && flutter analyze`(기준 69건 이하, 신규 0) `&& flutter test` 통과.
- 요청한 것만 지운다. 무관한 리팩터링 금지.
